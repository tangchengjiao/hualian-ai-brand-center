# 见舟与华链统一发布

为用户选定的项目复用统一品牌资料，并让用户能找到实际交付物。品牌中心是当前配置来源；本技能不另外保存微信号、报价和公共链接的副本。

## 默认执行约定

用户已经明确授权：以后让 Codex 上传自有新项目到 GitHub，即默认按本标准完成，不需要再次提醒或单独确认是否加入二维码。把统一联系区作为该次上传工作的一部分，只有用户在当前任务明确排除时才跳过。

GitHub 始终保留项目源码、公开资产、历史与部署资料；换服务器或托管平台不删除仓库。官网优先复用用户现有的 Cloudflare Pages 路线，实际入口以品牌中心中已经验证的地址为准，不固定依赖 chatgpt.site。

## 开始时读取

1. 目标项目适用的 `AGENTS.md` 与当前 README。
2. `D:/见舟品牌与发布中心/统一发布标准.md`。
3. `D:/见舟品牌与发布中心/public/brand.json`。

品牌中心不存在时先定位它，无法找到再向用户询问。不要凭旧聊天重建号码或网址。

## 工作范围

- 延续当前会话已有授权。用户只要方案时，整理标准或预览即可；不得因此推送所有仓库或发布网站。
- 用户要求整理或发布具体项目时，完成该项目的 README、交付物和统一联系区，并在已授权范围内提交、上传或部署。
- “按统一标准”意味着复用规则，不意味着获得任意仓库的无限期写入权限。批量工作以用户本次指定范围为准。
- 不创建后台监控。新仓库通过项目初始化或发布动作接入；有必要时在新项目的 `AGENTS.md` 中简短指向本标准。

## 项目接入

先核对源码、实际版本和交付文件，再写项目介绍。下载/体验入口放在容易找到的位置；软件下载指向真正的安装程序或交付包。

统一联系区放在 README 末尾。已有未标记的“联系见舟”“联系方式”等区块时，先将原区块迁移为标准联系区，避免重复追加。保留项目主体说明、用户正在编辑的内容和项目自己的下载入口。

使用品牌中心脚本预览或应用联系区：

```powershell
python "D:/见舟品牌与发布中心/scripts/sync_readme.py" --repo "目标项目目录"
python "D:/见舟品牌与发布中心/scripts/sync_readme.py" --repo "目标项目目录" --apply
```

脚本不上传、不提交、不推送。它只更新标记联系区和需要的二维码图片副本。应用后检查 diff，确认只有本次预期变更。

## 共用资料

- 品牌、个人身份、账号和二维码从 `brand.json` 和对应素材文件取得。
- README 末尾必须实际展示微信、抖音、视频号、公众号四张二维码图片；仅放微信或仅写其他渠道的账号不算完成。发布后检查 GitHub 渲染结果与四张图片加载情况。
- 华链 AI 是企业服务品牌，见舟是个人品牌与咨询联系人，不自行添加职务或身份。
- 公共链接为 `null` 时省略对应入口，不创建看似已上线的 URL。二维码公共地址缺失时使用脚本的本地图片回退。
- 官网发布后，将已验证的长期链接写回中心配置，再同步目标仓库。改中心配置不会自动改写历史 README。
- 官网迁移时一并迁移公开二维码和宣传册，让访客读取网站本身的资源；更新品牌中心后再同步 README，避免国内页面依赖 GitHub 原始图片地址。
- 企业宣传册从中心公开下载目录复用；完整报价只留在本地私有资料或独立私有仓库。公开页面展示精选参考价，完整报价联系微信获取。
- 更新源资料后，检查是否需要同步企业官网和本次范围内的仓库。没有用户要求时不修改其他仓库。

## 文件发布与核对

需要 Cloudflare 上线、迁移或排障时，读取 [Cloudflare 发布闭环](references/cloudflare-release.md)，使用品牌中心 scripts/cloudflare_pages.py；参考中保留本次实际验证的方法、备用传输和停止重复重试的条件。

普通新项目保持华链企业服务链接，仅更新自身的体验或下载入口。只有用户要求迁移企业官网时，才修改品牌中心公共地址并同步其他仓库。仅上传 GitHub 不代表要求创建网站。

源码和必要文档进项目仓库；软件安装程序、DMG 和交付 ZIP 进项目 Releases。安装后的主程序目录、卸载器和本地依赖不作为标准安装包上传。

发布前后按实际变更核对：版本、下载链接、图片展示、文档路径和本次 diff。文档与联系区变更无需重跑整套应用回归。结束时报告完成位置、可用入口，以及仍未发布的部分。
